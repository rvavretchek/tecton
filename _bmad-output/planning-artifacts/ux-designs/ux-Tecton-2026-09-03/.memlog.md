- (decision) Fontes confirmadas: ARCHITECTURE-SPINE.md (AD-10), UML.md (1.4), prd.md (FR-6..FR-8, §6.2), sprint-change-proposal-2026-09-02.md (Proposta D). Escopo fixado pelo caller: só telas do Directory Service (/admin) — árvore de objetos (leitura de estrutura, sem drag-and-drop) e formulário de edição de atributos via @rjsf/core a partir de objectClass.attributes. Fora de escopo: identidade de marca arbitrária, telas de domínio de terceiros.
- (decision) North Star (visão final, roadmap, não MVP): protagonista Marina, gerente de TI de empresa média que trocou de fornecedor pra um sistema construído em Tecton. Quer criar grupo, dar acesso, arrastar usuários pra dentro do grupo, gerenciar visualmente quem acessa o quê — tudo é objeto. Referência explícita: NDS da Novell (árvore + drag-and-drop + clique direito), contraste com Active Directory antigo (pouco usado por interface difícil). Ela desistiria se a função de árvore/permissão funcionasse errática ou de forma limitada. Esse brain dump ancora o EXPERIENCE.md como visão de longo prazo — o escopo desta sessão (MVP, FR-8/§6.2) é só navegação de leitura + formulário de atributo; drag-and-drop é roadmap explícito (reaproveitar implementação do Aether, per Brief).
- (decision) Árvore MVP usa linguagem visual clássica NDS/AD (ícones por objectClass, indentação, expand/collapse) para já preparar o terreno da visão final sem redesenho futuro. Clique direito no MVP abre menu contextual só com ações que o MVP realmente tem (Editar atributos, Ver detalhes) — sem cursor de arrastar, sem drop-zone highlight, nada que sugira drag-and-drop ainda não implementado. Mesmo componente evolui pra DnD no roadmap (reaproveitando Aether).
- (assumption) Form-factor: web (SPA em /admin, per AD-10) — desktop-first, consistente com a própria natureza de um console de diretório (NDS/AD também eram desktop-first); não travando responsividade mobile como requisito, já que não veio do usuário e a categoria de produto (console admin de diretório) tradicionalmente não prioriza isso.
- (decision) Busca/filtro por nome incluída no MVP dentro do painel de árvore — expande até o nó resultado e destaca, sem tocar na restrição de drag-and-drop.
- (decision) Visibilidade de ACL na árvore: nó sem permissão de leitura fica completamente invisível (não aparece bloqueado/cinza) — consistente com a postura Zero Trust do framework (não revela existência de objetos fora do acesso do usuário).
- (event) IA fechada: superfície única /admin (master-detail: árvore à esquerda com busca/filtro, detalhe/formulário à direita), com estados vazio/carregando/erro/permissão cobertos. Confirmado pelo usuário sem adições.
