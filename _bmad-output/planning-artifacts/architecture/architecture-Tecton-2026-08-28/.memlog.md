- (direction) Modo de trabalho: Coaching path (mesmo ritmo do PRD)
- (direction) Deliverables: spine de arquitetura + documentação UML em Markdown+Mermaid (componentes/domínios, sequência para sensitive.quorum/approval e extract/Strangler Fig, possivelmente classes/ER do Core de Diretório). Público: uso próprio do autor e futuros colaboradores, sem necessidade de material de apresentação polido pra revisor externo agora (SM-3 do PRD fica pra depois, se/quando precisar)
- (decision) Paradigma de design confirmado pelo autor: DOMA (Domain-Oriented Microservice Architecture) no nível macro (domínios como bounded contexts com fronteira/contrato explícitos) + Hexagonal/Ports-and-Adapters por serviço no nível micro (Providers do PRD são as portas: AuthProvider, KeyCustodyProvider, ServiceDiscoveryProvider, ConfigProvider, WorkflowEngineProvider, TokenRevocationStore). Não é decisão nova, é nomear formalmente o que o PRD já decidiu implicitamente
- (decision) Core de Diretório é um serviço próprio (opção 1): hospeda Tenant + Usuário/Grupo + Custodiante juntos num único 'serviço de diretório' do framework, com uma Closure Table fisicamente unificada. Isso é uma exceção explícita à regra geral de persistência-por-serviço do Glossário do PRD, justificada por serem domínios framework-provided (não escaneados por generate domain), inspirados em serviço de diretório centralizado real (NDS/Active Directory). Domínios de terceiros (Catálogo, Relatórios etc.) continuam cada um com seu próprio banco, sem exceção
- (version) TypeScript fixado em 6.0.3 (última release da implementação classica em JS) em vez de 7.0 (native Go compiler, GA em jul/2026) - TS 7 quebra ts-node e tsx (issue confirmada, API de compilador ainda instável), e tsx watch é mecanismo de live reload da FR-15. Revisitar quando o ecossistema tsx/testing acompanhar
- (version) Valkey adotado no lugar de Redis em toda a stack (Streams, rate limiting, TokenRevocationStore, Dev Services) - Redis Ltd mudou de BSD-3 para SSPL/RSALv2 em 2024, Valkey é o fork Linux Foundation BSD-3, clientes Node compatíveis sem mudança, sem gap de feature pro uso do Tecton (só primitivos puros). Mesmo raciocínio da troca Vault->OpenBAO já feita no PRD. Decisão propagada para PRD, brief, addendum do brief e docs/aether-tecton-compatibility.md (pendência de baixa relevância registrada pro lado do Aether)
- (version) Stack confirmado e verificado na web em 2026-08-28: Node.js 24 (Active LTS, suportado até abr/2028), Fastify 5.12.x, Prisma 7.8.x (100% TypeScript, sem engine Rust, stack trace mais legível - reforça objetivo 2 de ser IA-friendly)
- (decision) Directory Service (Tenant+Usuário/Grupo+Custodiante) nasce como serviço pronto/configurável, distribuído como pacote versionado do próprio Tecton (@tecton/directory ou equivalente) - NUNCA copiado/scaffolded pro repo do dev, ao contrário de domínios de negócio via generate domain. Customização só via objectClass.attributes declarativo no manifest, nunca editando lógica interna. Mesma postura 'nunca reimplementar, sempre integrar' já aplicada ao Custodiante (Constitution §7). Define regra de dependência: pacotes @tecton/* são importados como dependência versionada, nunca copiados pro código gerado; nenhum domínio de negócio importa código interno de outro domínio ou do Directory Service
- (decision) Terceiro eixo de idioma confirmado (distinto de docs-PT-BR vs código-inglês): mensagens/superfícies expostas ao usuário final do sistema GERADO pelo Tecton (corpo de erro RFC 9457 title/detail, UI React gerada via react-jsonschema-form, telas do Directory Service) são multi-idioma - PT-BR principal, EN secundário, extensível. CLI (tecton-admin) fica de fora, só inglês (público é dev/agente de IA). Mecanismo: RFC 9457 type continua URI neutra de idioma; title/detail negociados por Accept-Language; campo de extensão i18nKey pra lookup de máquina. Framework ship PT-BR+EN pras próprias superfícies (Directory Service, boilerplate de erro); fornece infraestrutura de i18n (catálogo de mensagens) pra domínios do dev, sem obrigar tradução do código de terceiros - é possível, não obrigatório
